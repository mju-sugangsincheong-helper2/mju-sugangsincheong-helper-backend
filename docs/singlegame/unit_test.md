수강신청 싱글 게임 서비스의 비즈니스 로직과 알고리즘을 격리하여 검증하기 위한 **매우 상세하고 구체적인 단위 테스트(Unit Test) 명세서**입니다.

이 명세서는 실제 프로그램 코드를 배제하고, **어떠한 조건과 경계값을 주입했을 때 어떠한 연산 결과를 반환받아 검증해야 하는지**에 초점을 맞추어 작성되었습니다.

## 1. 입력 데이터 및 도메인 규칙 유효성 검증 테스트
사용자가 게임을 종료(완료 혹은 타임아웃)하고 전송한 원본 데이터가 비즈니스 제약 조건을 준수하는지 검증하는 단위 테스트입니다.

### A. 과목 개수 종목의 유효성 검증
* **검증 대상:** 게임 결과 데이터의 총 과목 수(`totalCourses`) 필드
* **테스트 케이스:**
  * **정상 케이스:** 허용된 5가지 값인 `1`, `3`, `6`, `7`, `8`을 주입했을 때 유효성 검증을 정상 통과하는지 확인합니다.
  * **비정상 케이스 1:** 경계값 외부의 숫자인 `0`, `9`, `-5` 등을 주입했을 때, 비즈니스 에러나 유효성 예외가 정의된 예외 클래스로 던져지는지 확인합니다.
  * **비정상 케이스 2:** 허용되지 않는 범위 안의 숫자인 `2`, `4`, `5` 등을 주입했을 때도 비정상 케이스로 분류되어 차단되는지 확인합니다.

### B. 게임 상태와 상세 기록 간의 정합성 검증
* **검증 대상:** 올클리어 여부(`isCompleted`)와 전송된 상세 기록 목록(`details`) 개수 간의 관계
* **테스트 케이스:**
  * **올클리어 성공 시 케이스:** `isCompleted = true`이면서 선택 과목이 `6`개일 때, 상세 기록 목록의 개수가 정확히 `6`개인지 검증합니다. 만약 상세 기록의 개수가 이보다 부족하거나 초과할 경우 데이터 유효성 실패를 발생시키는지 확인합니다.
  * **타임아웃 실패 시 케이스 (60초 타임아웃):** `isCompleted = false`이고 선택 과목이 `6`개일 때, 상세 기록 목록의 개수가 전체 과목 수(`6`개)보다 적은 임의의 개수(예: `3`개)여도 정상적인 부분 기록으로 인지하여 저장 통과되는지 확인합니다.
  * **모순 데이터 케이스:** `isCompleted = false`인데 상세 기록의 개수가 선택 과목인 `6`개와 동일하게 넘어오는 경우, 혹은 `isCompleted = true`인데 상세 기록 개수가 부족한 모순이 발생할 때 올바르게 차단하는지 검증합니다.

### C. 반응 속도 지표의 음수 및 영(0)값 차단 검증
* **검증 대상:** 모든 반응 속도 밀리초(ms) 지표 (`tEnterMain`, `tClickCourse`, `tClickYes`, `tClickOk`)
* **테스트 케이스:**
  * **최소 반응 속도 미달 케이스:** 인간의 물리적 반응 속도로서 불가능한 수치인 `0ms` 또는 `음수(-100ms)`가 입력 필드 중 단 하나라도 포함되어 전송될 경우, 데이터 거부 예외를 발생시키는지 검증합니다.
  * **비정상적으로 너무 큰 값 케이스:** 타임아웃 제한 조건인 60초(`60,000ms`)를 초과하는 수치(예: `65,000ms`)가 포함되어 있을 때 유효성 검증을 통해 유실되거나 거부되는지 확인합니다.

## 2. 정량 분석 지표 계산 엔진 테스트
데이터베이스 조회 없이, 입력된 원순수 반응 속도 값들을 바탕으로 백엔드 내부 연산 로직이 정해진 공식대로 수학적 정합성을 갖추는지 확인하는 테스트입니다.

### A. 과목별 순수 처리 속도($T_i$) 합산 검증
* **검증 대상:** $T_i = \text{t\_click\_course}_i + \text{t\_click\_yes}_i + \text{t\_click\_ok}_i$
* **테스트 케이스:**
  * 과목 상세 항목으로 조준 속도 `450ms`, 1차 승인 속도 `180ms`, 2차 연타 속도 `200ms`를 주입합니다.
  * 계산기가 이 값들을 빠짐없이 더해 결과값 `830ms`를 산출해 내는지 검증합니다.

### B. 초반 스퍼트 속도 (Initial Sprint Speed) 연산 검증
* **검증 대상:** $T_1 - \frac{1}{N-1} \sum_{i=2}^{N} T_i$ (단, $N \ge 3$)
* **테스트 케이스:**
  * **스퍼트 성공 케이스:** 3개 과목 소요 시간이 각각 $T_1 = 600\text{ms}$, $T_2 = 1000\text{ms}$, $T_3 = 1100\text{ms}$로 입력되었을 때, 공식 연산 결과가 마이너스 값인 `-450.0ms`로 정확히 도출되는지 확인합니다.
  * **스퍼트 실패 케이스 (초반 지체):** 3개 과목 소요 시간이 각각 $T_1 = 1200\text{ms}$, $T_2 = 800\text{ms}$, $T_3 = 800\text{ms}$로 입력되었을 때, 연산 결과가 플러스 값인 `+400.0ms`로 정확히 도출되는지 확인합니다.
  * **제외 조건 케이스:** 과목 수가 $N = 1$일 때 해당 계산을 요구하면 에러를 유발하지 않고, 안전하게 `null` 또는 연산 제외 상태값으로 리턴하는지 검증합니다.

### C. 페이스 유지도 (Pace Deviation) 연산 검증
* **검증 대상:** $T_i$ 평균에 대한 모표준편차 $\sigma$ 연산 (단, $N \ge 3$)
* **테스트 케이스:**
  * **기복 없는 기계적 페이스 케이스:** 3개 과목 소요 시간 $T_1 = 800\text{ms}$, $T_2 = 800\text{ms}$, $T_3 = 800\text{ms}$를 주입했을 때, 표준편차가 완벽하게 `0.0`으로 검증되는지 확인합니다.
  * **불안정한 기복 페이스 케이스:** 소요 시간 $T_1 = 500\text{ms}$, $T_2 = 1000\text{ms}$, $T_3 = 1500\text{ms}$를 주입했을 때, 평균값 `1000.0ms`를 기준으로 한 표준편차가 대략 `408.25ms`로 정확하게 계산되는지 소수점 정밀도를 확인합니다.
  * **제외 조건 케이스:** $N = 1$일 때 해당 연산을 건너뛰고 빈 값을 반환하는지 검증합니다.

## 3. 맞춤형 피드백 코드 판정 엔진 테스트
사용자의 백분위 성적 정보를 바탕으로 사전에 정해진 규칙 엔진이 상호 배타적이고 정확하게 하나의 결과값만을 출력하는지 확인하는 테스트입니다.

### A. 피지컬 밸런스 (Aiming vs. Burst) 축 규칙 분기 검증
* **검증 대상:** 조준 백분위($Aim_p$)와 연타 백분위($Burst_p$)를 주입해 1순위부터 5순위까지 순서대로 매핑되는지 검증
* **테스트 케이스:**
  * **[1순위 검증] `GOD_TIER_PHYSICAL`:** 에임 백분위 `30.0%`, 버스트 백분위 `30.0%`를 주입했을 때, 경계선 내부(30% 이하)에 포함되므로 `GOD_TIER_PHYSICAL`이 산출되는지 확인합니다.
  * **[2순위 검증] `PHYSICAL_UPGRADE_NEEDED`:** 에임 백분위 `70.0%`, 버스트 백분위 `70.0%`를 주입했을 때, 경계선 바깥(70% 이상)에 포함되므로 `PHYSICAL_UPGRADE_NEEDED`가 산출되는지 확인합니다.
  * **[3순위 검증] `FAST_BUT_INACCURATE`:** 에임 백분위 `70.0%` (느림), 버스트 백분위 `30.0%` (빠름)를 주입했을 때, 조건 우선순위에 따라 `FAST_BUT_INACCURATE`가 성공적으로 매칭되는지 확인합니다.
  * **[4순위 검증] `SLOW_AIM`:** 위의 1~3순위 조건에 걸리지 않으면서, 에임 백분위 `55%`, 버스트 백분위 `45%`를 주입했을 때, 에임 백분위가 더 커서 상대적으로 느리므로 `SLOW_AIM` 코드가 판정되는지 확인합니다.
  * **[5순위 검증] `SLOW_BURST`:** 위의 1~4순위 조건에 모두 부합하지 않는 나머지 상태(예: 에임 백분위 `45%`, 버스트 백분위 `55%`)를 입력하여 정상적으로 최종 잔여 조건인 `SLOW_BURST`로 분기되는지 확인합니다.

### B. 진입 및 초반 포지셔닝 (Entry & Start) 축 규칙 분기 검증
* **검증 대상:** 진입 반응속도 백분위($E_p$)와 1순위 과목 처리 속도 백분위($Start_p$) 간의 우선순위 연산
* **테스트 케이스:**
  * **[1순위 검증] `PERFECT_ENTRY_START`:** 진입 백분위 `29%`, 1순위 백분위 `30%` 입력 시 `PERFECT_ENTRY_START`가 출력되는지 확인합니다.
  * **[2순위 검증] `ENTRY_MASTER_START_NOVICE`:** 진입 백분위 `30%` 이하(예: `20%`), 1순위 백분위 `70%` 이상(예: `80%`) 입력 시 `ENTRY_MASTER_START_NOVICE`가 판정되는지 확인합니다.
  * **[3순위 검증] `ENTRY_LATE_START_MASTER`:** 진입 백분위 `70%` 이상(예: `75%`), 1순위 백분위 `30%` 이하(예: `15%`) 입력 시 `ENTRY_LATE_START_MASTER`가 판정되는지 확인합니다.
  * **[4순위 검증] `NEED_FASTER_ENTRY`:** 진입 백분위 `70%` 이상(예: `70%`), 1순위 백분위가 `30%` 초과(예: `31%`)일 때 `NEED_FASTER_ENTRY` 조건 충족 여부를 확인합니다.
  * **[5순위 검증] `START_HESITATION`:** 모든 상위 조건이 거짓인 평이한 수치(예: 진입 `50%`, 1순위 `50%`) 입력 시 `START_HESITATION`이 산출되는지 검증합니다.

### C. 페이스 및 멘탈 제어 (Pace & Focus) 축 규칙 분기 검증
* **검증 대상:** 표준편차 백분위($\sigma_p$), 평균값($\mu$), 전반/후반 차이, 지연 마커를 활용한 심리 상태 검증 (과목 수 $N \ge 3$ 이상인 경우에만 한정 동작)
* **테스트 케이스:**
  * **비활성화 검증:** 플레이한 총 과목 수 $N = 1$일 때, 페이스 평가 모듈 자체가 작동하지 않고 결과 상태값에서 제외되는지 사전에 검증합니다.
  * **[1순위 검증] `MACHINE_LIKE_PACE`:** 편차 백분위 $\sigma_p = 30.0\%$ 이하 값을 주입했을 때, 다른 복잡한 조건(지연 여부 등)을 모두 제치고 최우선 조건인 `MACHINE_LIKE_PACE`가 반환되는지 확인합니다.
  * **[2순위 검증] `EASY_PANIC`:** 편차 백분위가 `30%`를 초과하는 불규칙한 상태에서, 클라이언트가 전달한 과목 상세 배열 중 "가짜 대기열 발생" 마커가 표시된 직후 순서의 과목 소요 시간 $T_i$가 전체 평균 $\mu + 1.5\sigma$보다 큰 경우, 멘탈 무너짐 상태인 `EASY_PANIC` 코드를 도출하는지 확인합니다.
  * **[3순위 검증] `STRONG_FINISHER`:**
    * 전반부 평균 시간과 후반부 평균 시간의 차이를 대조합니다.
    * 홀수 과목 수($N=7$)가 주어졌을 때 정중앙 과목(4번째 과목)을 제외하고, 전반부(1~3과목) 평균 시간이 후반부(5~7과목) 평균 시간보다 `100ms` 이상 느릴 때(즉, 후반부가 100ms 이상 빠를 때) `STRONG_FINISHER`가 성공적으로 추출되는지 검증합니다.
  * **[4순위 검증] `WEAK_FINISHER`:** 후반부 과목 평균 시간이 전반부 과목 평균 시간보다 `100ms` 이상 지체될 때(즉, 후반부가 느려질 때) `WEAK_FINISHER`를 도출하는지 확인합니다.
  * **[5순위 검증] `FLUCTUATING_PACE`:** 위 1~4순위에 모두 해당하지 않고 시간 변동 폭만 존재하는 무작위 데이터를 주입했을 때 `FLUCTUATING_PACE`를 반환하는지 확인합니다.

## 4. 백분율 통계 및 매퍼(Mapper) 검증 테스트
데이터베이스 조회용 엔티티 객체나 통계 뷰의 원본 가공 데이터를 API 전송 규격에 부합하는 클라이언트용 JSON 구조(DTO)로 변환할 때의 정합성 검증입니다.

### A. 백분율(Percentile) 환산 연산 검증
* **검증 대상:** 석차(`rank`)와 전체 참가자 수(`totalParticipants`) 정보를 바탕으로 백분율을 도출하는 내부 변환 메서드
* **테스트 케이스:**
  * **상위권 경계:** 전체 참가자 수가 `3,200`명이고, 본인의 석차가 `142`등일 때 백분율 수식이 상위 `4.4375%`로 소수점 아래 첫째 자리까지 정확하게 반올림 처리(`4.4%`)되어 DTO에 바인딩되는지 검증합니다.
  * **단일 참가자 상황:** 전체 참가자 수가 `1`명이고, 석차가 `1`등일 때 분모 나눗셈 예외(Divide by Zero)가 나지 않고 안전하게 `100.0%` 또는 `0.0%`로 규격에 맞추어 처리되는지 확인합니다.

### B. NULL 필드 가공 처리 검증
* **검증 대상:** API 반환 객체 빌더 및 매퍼
* **테스트 케이스:**
  * 단일 과목($N=1$) 게임 결과 데이터 객체를 조회 데이터에서 받아 DTO로 매핑할 때, 스퍼트 속도(`initialSprintSpeed`)나 페이스 유지 편차(`paceDeviation`) 같은 수식 필드들이 예외를 터뜨리지 않고 안전하게 JSON 상에서 `null` 값으로 치환 및 직렬화 준비가 완료되는지 검증합니다 [1].
