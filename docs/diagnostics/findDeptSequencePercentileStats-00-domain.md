# 분석 응답의 도메인 획정 (00)

> 이 문서는 용어 정의만 한다. 쿼리·인덱스(01), 성능 실측(02)과 분리.

---

## 1. 등장인물 3개

- **낱개 기록**: 누구의 게임 1판. (`gameId` 1개 = `single_game` 1행 + detail N행) 단 랭킹 정보는 붙어서 나간다. (요청자와 해당 게임 판의 주인이 다를 수 있음)
- **전체 통계**: 같은 과목수 전체의 분포 기준선. (p10·p30·p50·p70)
- **학과 통계**: 같은 과목수 + 같은 학과의 분포 기준선. (p10·p30·p50·p70)

통계 2개가 **캐시 대상 전부**다. 낱개 기록은 캐시하지 않는다.

- **상위 백분위·등급**: 독립 데이터가 아니라 파생값. 낱개 기록 1개를 전체 통계에 대입해 계산한다. 학과 통계는 쓰지 않는다.

## 2. 규칙 3개

1. 실제 요청은 항상 **낱개 기록 1개**다. 응답에 통계가 **덧붙어서** 나간다.
2. 전체 통계는 항상 붙는다.
3. 학과 통계는 **판 주인의 학과** 것으로 붙는다. 판 주인이 게스트(학과 없음)면 안 붙는다.

## 3. 경우 4개

| 판 주인 | 보는 사람 | 나가는 것 |
|---|---|---|
| A (컴공) | A | A판 + 전체 + 컴공 |
| B (경영) | A | B판 + 전체 + 경영 |
| 게스트 | A | 그 판 + 전체만 |
| 학과 없는 회원 | A | 그 판 + 전체만 |

## 4. 헷갈리지 않게 말하는 법

- ❌ "학과 데이터" → ⭕ "판 주인의 학과 통계"
- ❌ "A의 통계" → ⭕ "A판에 붙은 통계" (보는 사람 A와 구별하기)
- 문장 틀: **"X의 판을 보면, 전체 통계와 X 학과의 통계가 붙는다."**

## 5. 집계 단위 (확정)

- 낱개 기록에 붙는 **랭킹은 사람 기준**. 인당 대표 1판으로 순위를 매긴다.
- **통계(전체·학과)는 판수 기준**. 완료된 판 전부로 분포를 만든다.

즉 같은 과목수라도 랭킹 분모는 사람 수, 통계 표본은 판 수로 다르게 센다.

## 6. 학과 기준 (확정)

- 요청자(보는 사람)는 학과 기준에 쓰지 않는다. **판 주인이 유일한 기준**이다.
- 따라서 `ranking.department`도 판 주인 학과로 붙인다. (현재 코드는 보는 사람 기준이라 수정 대상 → `buildRankingSummary`가 `gameOwner` 학과를 쓰도록.)

## 7. 동점 정책 (확정)

- 동점자는 같은 순위, 다음 순위는 건너뛴다. (1, 2, 2, 4식, standard competition ranking)
- 현재 코드 2곳 모두 다름 (수정 대상):
  - 내 순위(`computeRank`, `t_total <=` 카운트): 블록의 마지막 번호를 줌 (1, 4, 4, 4, 5식).
  - 랭킹판(`findRankingRaw` 계열, `ROW_NUMBER`): 동점 무시 연속번호 (1, 2, 3, 4, 5식).
- 구현 방향 (확정): 내 순위는 `COUNT(*)` 방식. `나보다 엄격히 앞선 판 수 + 1` (동점 tiebreak는 `created_at`). 랭킹판 TOP N 표시가 필요할 때만 `RANK()` + DB `LIMIT` 사용. (이유: 내 순위 1개에 전체 정렬은 과함.)
