# 싱글게임 도메인 획정 (00)

> 이 문서는 용어 정의 + 규칙만 한다. 싱글게임 전체(API 5개)를 다룬다.
> 쿼리·인덱스(01-analysis), 구조·쿼리 목록(api-01·api-02)과 분리.

---

## 1. 사람 2명

- **요청자**: API를 호출한 사람 (`memberId`). 보는 사람이다. 기록의 주인과 다를 수 있다.
- **판 주인**: 게임 기록의 소유자 (`game.memberId`). 요청자와 같은 사람일 수도, 남일 수도 있다.
- **게스트**: 학과가 없는 사람. 요청자가 게스트일 수도, 판 주인이 게스트일 수도 있다.

## 2. 데이터 3개 + 파생값

- **낱개 기록**: 판 1개의 원본. (`game` 1행 + `detail` N행)
- **전체 통계**: 같은 과목수 전체의 분포 기준선. (p10·p30·p50·p70)
- **학과 통계**: 같은 과목수 + **판 주인 학과**의 분포 기준선. (p10·p30·p50·p70)

통계 2개가 **캐시 대상 전부**다. 낱개 기록은 캐시하지 않는다.

- **상위 백분위·등급**: 독립 데이터가 아니라 파생값. 낱개 기록 1개를 전체 통계에 대입해 계산한다. 학과 통계는 쓰지 않는다.
- **랭킹**: 파생값. 사람 기준으로 인당 대표 1판(최고 기록)으로 매긴다. 판 건수가 아니다 (§5).

## 3. API별 누구 기준으로 붙나

| API | 나가는 것 | 기준 |
|---|---|---|
| POST 저장 | 저장 결과만 | 요청자 존재 확인만 한다 |
| analysis | 판 + 전체 통계 + (조건부) 학과 통계 | 학과 통계는 **판 주인** 기준. 요청자로 따지는 건 `isOwner`뿐 |
| rank GLOBAL | 전체 순위 + myRank(전체) | myRank는 **요청자 본인** 최고 기록의 전체 순위 |
| rank DEPARTMENT | 학과 순위 + myRank(학과) + 적용 학과(`department`) | 학과 지정 시 그 학과, 생략 시 **요청자 학과**. 학과 없는 요청자는 사용 불가 400 (`SINGLEGAME_INVALID_RANK_DEPARTMENT`) |
| my | 요청자 본인 판 목록 (순위 없음) | 요청자 = 판 주인이라 기준 충돌 없음 |
| departments | 학과 목록 | 없음 |

## 4. 경우 4개 (analysis)

| 판 주인 | 요청자 | 나가는 것 |
|---|---|---|
| A (컴공) | A | A판 + 전체 + 컴공 |
| B (경영) | A | B판 + 전체 + 경영 |

## 5. 집계 단위 (확정)

- 낱개 기록에 붙는 **랭킹은 사람 기준**. 인당 대표 1판으로 순위를 매긴다.
- **통계(전체·학과)는 판수 기준**. 완료된 판 전부로 분포를 만든다.

즉 같은 과목수라도 랭킹 분모는 사람 수, 통계 표본은 판 수로 다르게 센다.

## 6. 학과 기준 (확정)

- 요청자(보는 사람)는 학과 기준에 쓰지 않는다. **판 주인이 유일한 기준**이다.
- 따라서 analysis의 학과 랭크도 판 주인 학과로 붙인다. (수정 예정 — 현재 코드는 보는 사람 기준)
- 단 rank 조회에서 학과를 생략했을 때 요청자 학과를 쓰는 건 예외가 아니다.
  그건 데이터 귀속 기준이 아니라 조회 조건의 기본값이다. 붙는 통계·랭킹의 학과는 여전히 판 주인 기준이다.

## 7. 동점 정책 (확정)

- 동점자는 같은 순위, 다음 순위는 건너뛴다. (1, 2, 2, 4식, standard competition ranking)
- rank 목록·myRank는 수정됨: 사람 기준 COUNT + 블록 첫 번호.
- analysis는 수정 예정. 현재 코드 2곳이 서로 다름:
  - 내 순위(`computeRank`, `t_total <=` 카운트): 블록의 마지막 번호를 줌 (1, 4, 4, 4, 5식).
  - 학과 랭크(`findDeptRankedGameIds` 자바 루프): 위치 탐색이라 동점 처리 없음.
- 구현 방향 (확정): `나보다 엄격히 앞선 판 수 + 1` COUNT(*) 방식. (동점 tiebreak는 `created_at`).
  my에 쓴 `countBetterTTotal`·`countBetterDeptTTotal`·`countDeptGames`를 analysis에도 재사용한다.

## 8. 헷갈리지 않게 말하는 법

- ❌ "학과 데이터" → ⭕ "판 주인의 학과 통계"
- ❌ "A의 통계" → ⭕ "A판에 붙은 통계" (보는 사람 A와 구별하기)
- ❌ "내 학과 랭킹" → ⭕ "학과를 생략했을 때 요청자 학과로 보는 순위" (학과를 적으면 그 학과)
- ❌ "최신판 순위" → ⭕ "대표판(최고 기록) 순위" (myRank는 최신판이 아니라 최고 기록 기준)
- 문장 틀: **"X의 판을 보면, 전체 통계와 X 학과의 통계가 붙는다."**
